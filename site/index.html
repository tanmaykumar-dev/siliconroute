The problem

Hardware load balancing cannot rely on common laptop assumptions.

"Always use the GPU"
For small models, CPU is faster than discrete GPU at batch 1 ( vs ) because GPU kernel launch and PCIe overhead dominate compute time.
"Always use the CPU"
For compute-bound workloads, discrete GPU is faster than CPU ( vs ), massively reducing execution latency under sustained load.
"The fastest chip is fixed"
Cold starts invert the winner. Discrete GPU first inference incurs a overhead due to session creation and shader compilation, making the CPU faster for one-shot tasks.
Architecture

How it works

A closed measurement and learning loop that runs entirely on your laptop.

1

Measure

Benchmarks real neural network executions across CPU, iGPU, and dGPU, capturing median millisecond timings and power states.

2

Learn

Fits physics-based hardware performance models (overhead + compute FLOPs + bandwidth bytes) with leave-one-out validation.

3

Decide

Evaluates execution candidates against physical penalties (GPU wake state, session startup, battery power limits).

4

Verify

Benchmarks the selected chip against baseline alternatives on physical hardware to record real regret and confirm decisions.

Key findings

Key empirical insights uncovered during benchmark sweeps.

Kernel Launch Overhead

On small neural networks (MLP-256 at batch 1), CPU is faster than discrete GPU ( vs ).

Sustained Acceleration

On large models (MLP-3072 sustained), the RTX 5070 is faster than the CPU ( vs ).

Cold Start Startup Penalty

Creating an ONNX Runtime DirectML session on RTX incurs a overhead over sustained execution due to DirectX shader compilation.

Winograd Convolution Anomaly

conv-96 exhibits a slowdown on RTX vs conv-64, pointing to an algorithmic selection boundary in DirectML.

Honesty

Limitations

Extracted verbatim from the project README at build time.

  • FP32 only: All profiled models evaluate in float32. FP16 and INT8 acceleration are planned.
  • DirectML only on Windows: Execution uses DmlExecutionProvider; native CUDA is not used.
  • Synthetic model families: Parameterized MLP, Conv, and Attention topologies.
  • Session variability: Discrete GPU exhibits cross-session spread up to .
Reproduction

Reproduce it locally

Run on your laptop or verify the frozen SQLite database checksum.

1. Clone and install dependencies
git clone https://github.com/tanmay/siliconroute.git
cd siliconroute
py -3.12 -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
2. Launch local instrument dashboard
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
3. Verify frozen database checksum
Get-FileHash data/final/siliconroute_final.db -Algorithm SHA256
Expected SHA256: 98542cffb7264eee537d218e1863ccbbc174495e0bf13eb244ee22cd6f034cf5
