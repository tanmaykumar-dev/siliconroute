The Problem

Why static scheduling fails on modern heterogeneous laptop processors:

Small tasks run faster on the host CPU than on the discrete GPU. Driver initialization and DirectML launch overhead exceed computation time on small models.
Cold-start session initialization incurs severe latency overhead on discrete GPUs. For sporadic single inferences, waking the GPU causes large slowdowns unless routed to the CPU.
Operating systems swap GPU adapter enumeration indices during power transitions, silently sending workloads to the wrong physical silicon without hardware-level identity verification.

How It Works

An empirical feedback loop operating entirely on local hardware:

01
Measure
Runs real ONNX workloads across CPU, integrated GPU, and discrete GPU, storing latency distributions and physical telemetry in SQLite.
02
Learn
Fits non-negative least squares hardware performance rooflines per chip: time = overhead + FLOPs / compute + bytes / bandwidth.
03
Decide
Evaluates task dimensions, current P-states, and power scheme to route each task to the optimal silicon for fastest, battery, or thermal goals.
04
Verify
Benchmarks competing candidate processors on real silicon to confirm decisions and compute empirical regret against the ground-truth optimal choice.
