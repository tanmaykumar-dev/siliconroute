# Design decisions (append one line per decision: date - decision - why)

- Local web app on localhost instead of a hosted website - the whole point is on-device measurement; a cloud host cannot see the laptop's chips.
- FastAPI (Python) backend - ONNX Runtime, NVML and WMI are all Python-accessible, so one language and one process.
- SQLite in WAL mode - single local file, no server to install, readers never block the writer; busy_timeout avoids "database is locked".
- One benchmark job at a time - parallel benchmarks steal CPU/GPU from each other and corrupt measurements.
- ONNX Runtime execution providers - the same model file runs on CPU, each DirectML GPU, and (later) the Snapdragon NPU via QNN.
- Three predictor forms chosen per device by leave-one-out error - no single formula fits every chip; honest model selection.
- Router judged by decision accuracy and regret vs baselines (always-CPU, always-GPU, ORT policy) - ranking matters more than exact milliseconds.
- Native FastAPI SSE for live telemetry - simpler than WebSockets for one-way server-to-browser streams.
- No fake numbers in app code - every value traces back to a stored measurement; unavailable sensors show "not available".
- 2026-09-27 - DirectML probe without hardcoded names: query adapters 0..3 via minimal ONNX probe model session and verify sess.get_providers()[0] == 'DmlExecutionProvider' - DirectML indices are adapter positions, never guess GPU names.
- 2026-09-27 - CPU name resolution from Windows registry - platform.processor() returns generic family string on Windows; registry contains friendly brand name.
- 2026-09-27 - Exact synthetic FLOPs and parameter formulas matching SPEC Section 3 - enables principled predictor fits without guessing model compute requirements.
- 2026-09-27 - Single worker queue with in-memory lock rejecting concurrent benchmarks with HTTP 409 - prevents contention and protects timing accuracy.
- 2026-09-27 - CPU reference output verification using max relative error threshold 1e-2 - ensures chips giving corrupted numerical results are caught and flagged.
- 2026-09-27 - Adaptive inner-loop timing for sub-millisecond runs - loops k times per sample so sample duration >= 1 ms, preventing micro-jitter distortion on tiny models.
- 2026-09-27 - Robust spread metric (p90 - p10) / median with threshold 0.30 - avoids false 'unstable' flags caused by isolated background OS scheduler spikes.
- 2026-09-27 - DML duplicate adapter check via bit-identical outputs and <5% median diff across >= 3 runs - disables alias adapters without deleting history or guessing names.
- 2026-09-27 - Added 'software' device kind to accommodate Microsoft Basic Render Driver or CPU emulation identified in Phase 3.
- 2026-09-27 - Telemetry ring buffer of 3,600 samples with periodic 10s SQLite flushes and native FastAPI EventSourceResponse SSE - provides zero-lag live telemetry streaming without disk thrashing.
- 2026-09-27 - Dual-path energy measurement: NVML cumulative mJ hardware counter for NVIDIA dGPU and WMI root\\wmi BatteryStatus for whole-laptop battery delta - measures energy whether plugged in or discharging.
- 2026-09-27 - Sustained continuous warmup >= 300 ms for DML devices, cold-start first_run_ms tracking, and sample duration target >= 5.0 ms - ramps GPU out of low-power P-states (P8 -> P0/P2) and ensures <6% inter-session reproducibility.
- 2026-09-27 - Bootstrap 95% confidence interval of median with 1,000 resamples and ci_rel threshold 0.10 - statistically principled stability metric that accurately reflects sample confidence.
- 2026-09-27 - Attributed dml:1 as NVIDIA GeForce RTX 5070 Laptop GPU (58% NVML util under load) and dml:0 as AMD Radeon 610M iGPU via empirical identify load test.
- 2026-09-27 - Root cause of Phase 1 NVML 'Insufficient Permissions' (Untested Hypothesis): On hybrid laptops with NVIDIA Optimus / Advanced Optimus, when the discrete GPU is in D3cold power cutoff, querying privileged driver management interfaces without an active graphics context throws NVML_ERROR_NO_PERMISSION. Once DirectML opens an active adapter handle or the dGPU wakes into P8/P0, all unprivileged NVML telemetry queries succeed in a standard user process. Telemetry reader now retries every 30s rather than disabling NVML permanently.
- 2026-09-28 - Model selection via Leave-One-Out MAPE across 3 candidate forms (F1 roofline, F2 roofline+cache, F3 loglinear) - automatically selects the best physical formulation per compute chip based on true generalization error without overfitting.
- 2026-09-28 - Weighted NNLS minimization (1/t_ms weighting) for F1 and F2 - directly minimizes relative percentage error rather than absolute error, ensuring sub-millisecond runs are not drowned out by large multi-millisecond runs.
- 2026-09-28 - 2x extrapolation ceiling on crossover predictions - prevents ungrounded asymptotic predictions outside the empirically measured parameter envelope.
- 2026-09-28 - Auto-refit policy triggering every 10 new valid runs (REFIT_EVERY) and manual trigger via POST /api/fit - keeps hardware parameters continuously calibrated as new models are benchmarked.
- 2026-09-28 - Atomic SQLite database purge of synthetic test entities: single transaction with count verification preserving exactly 204 real runs across sessions 9, 17, 18, 32, 33, 38, 84 - eliminates all test contamination without touching production data.
- 2026-09-28 - Comprehensive production database protection under pytest: full sha256 fingerprint check across main db, -wal, and -shm files, with runtime path guard raising RuntimeError on any production db connection attempt during tests.
- 2026-09-28 - Equality and hash delegation on EngineProxy (__eq__ and __hash__) - ensures SQLAlchemy transaction connection tracking reuses the identical SQLite connection across query autoflush and session commit, eliminating 5-second SQLite lock timeouts.
- 2026-09-28 - Single JSON serialization for SSE telemetry events - passes dicts directly to FastAPI ServerSentEvent so clients receive parseable objects rather than double-encoded JSON strings.
- 2026-09-28 - Dual energy reporting: total energy per inference and energy above idle per inference with schema migration for energy_above_idle_mj_per_inf - separates hardware baseline standby consumption from compute load cost.
- 2026-09-28 - CPU frequency on Windows reported as None - psutil returns static base clock (2401 MHz) on Windows rather than real dynamic boost clock; per Hard Rule 1, store NULL instead of misleading constant data.
- 2026-09-28 - 500-round bootstrap 95% confidence intervals on physical parameters (t0, compute throughput, bandwidth) with reliability flags (>50% CI half-width marked not reliable) - provides transparent statistical certainty on hardware model coefficients.
- 2026-09-28 - High-resolution crossover evaluation over 250 log-spaced points uncovering empirical Batch 1 crossover at MLP width 1607 (10.33M params) where RTX 5070 overtakes CPU - CPU wins below 1607 due to lower command dispatch overhead (0.0138 ms vs 0.1558 ms), RTX 5070 wins above 1607 due to 3.68 TFLOP/s throughput.
- 2026-09-28 - Hardware architecture attribution: RTX 5070 uses GDDR7 memory; GPU startup cost (t0) is DirectML command dispatch and driver submission latency rather than PCIe bus transfer, confirmed by Radeon 610M iGPU exhibiting t0 = 0.1095 ms despite having no PCIe link.
- 2026-09-28 - Idle-gap GPU wake test: discrete GPU drops from active P0 to P4/P5 at 0.5s-2s and deep sleep P8 at 10s; a 30s idle gap incurs a 2.37 ms wake penalty (11.9x steady-state latency).
